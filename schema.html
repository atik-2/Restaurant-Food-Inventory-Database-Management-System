Remember it in 3 Groups

There are 10 tables. Easy way to remember — three groups + ekta login table:

GroupTablesMeaning
Stock side suppliers, ingredients, purchases Maal kothay theke ashe, koto ache
Menu side menu_items, recipes Ki khabar bikri hoy, tate ki ki lage
Sales side customers, employees, orders, order_items Ke order korlo, ke handle korlo, ki bikri holo

recipes is the bridge table: it connects the Menu side with the Stock side. Because of this table, selling one food item can automatically reduce the correct ingredients.

Normalization

FormRuleHow we did it
1NF No repeating groups; every cell holds one value An order's food items are not stored in one column — each item is a separate row in order_items
2NF Every non-key attribute depends on the whole primary key In recipes (PK = menu_id + ingredient_id), qty_required depends on both columns together
3NF No transitive dependency (non-key → non-key) Supplier name is not kept in ingredients; only supplier_id is stored and the name comes from the suppliers table
Benefit: no duplicate data, less storage, and no update anomaly — a supplier's phone number is changed in one place only.

DBMS Concepts Used

1. Primary Key

Unique identification of each row — e.g. order_id.

2. Foreign Key

Connects two tables and keeps data valid — e.g. orders.customer_id.

3. Constraints

NOT NULL, UNIQUE, CHECK, DEFAULT.

4. SQL Operations

INSERT, UPDATE, DELETE, SELECT.

5. Joins

INNER JOIN and LEFT JOIN to combine tables.

6. Views & Triggers

Views = saved reports. Triggers = automatic stock update.
